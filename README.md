# SmartTourniquet

**Апаратно-програмний комплекс оперативного контролю часових параметрів оклюзійних джгутів та автоматизації медичного сортування.**

Проєкт МАН України · секція «Електроніка та приладобудування».

Електронна кліпса на турнікет (CAT Gen 7 / SICH) на базі nRF52840: автоматично фіксує момент
накладання (геркон + магніт), веде хронометраж від кварцового RTC і передає дані медику через
BLE-маяк та NFC. Мобільний застосунок формує чергу тріажу за протоколом TCCC (ліміт 2 год).

## Структура репозиторію

```
SmartTourniquet/
├── firmware/                  Прошивка nRF52840 (Arduino IDE, ядро Adafruit nRF52)
│   └── SmartTourniquet/       Папка скетчу (назва = назва .ino — вимога Arduino IDE)
│       ├── SmartTourniquet.ino    Точка входу: лише setup()/loop() → Controller
│       ├── config.h               ВСІ налаштування: піни, пороги TCCC, BLE, таймінги
│       └── src/
│           ├── app/               Логіка верхнього рівня (кінцевий автомат пристрою)
│           ├── core/              Чиста логіка без заліза (тріаж, формат пакета) — тестується на ПК
│           ├── drivers/           Робота із залізом: геркон, кнопка, батарея, OLED
│           └── services/          Системні сервіси: таймер, BLE, NFC, живлення, збереження стану
│
├── app/                       Мобільний застосунок медика (Flutter)
│   └── smart_tourniquet_app/
│       └── lib/
│           ├── core/              Константи, моделі, форматування
│           ├── data/              Джерела даних: BLE-сканер, NFC-зчитувач, парсер пакета
│           ├── domain/            Бізнес-логіка: черга тріажу, RSSI-локатор
│           └── ui/                Екрани та віджети
│
├── tools/                     Утиліти для стенду/налагодження (Python BLE-монітор)
├── hardware/                  Схемотехніка, розпіновка, BOM, корпус
└── docs/                      Архітектура, протокол обміну, енергобюджет, план випробувань, матеріали МАН
```

## Принципи архітектури

1. **Один модуль — одна відповідальність.** Драйвер геркона нічого не знає про BLE, BLE нічого не знає про OLED.
2. **Залежності йдуть лише вниз:** `app → services/drivers → core`. `core` не залежить ні від чого.
3. **Усі «магічні числа» — в `config.h`** (прошивка) та `core/constants.dart` (застосунок).
4. **Формат пакета описаний один раз** — у [docs/protocol.md](docs/protocol.md) — і реалізований
   дзеркально в `core/beacon_packet.*` (прошивка), `data/ble/beacon_parser.dart` (застосунок) та `tools/ble_monitor.py`.
